<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI terminal → shared coordinator | Untrusted pasted input and operator-visible QR/status values cross into shared pairing logic. |
| Deno relay pool → BuildSigner | Relay messages and lifecycle events cross from a runtime-specific transport. |
| CLI process → OS credential provider | Reusable signer material crosses into platform-protected persistence. |
| BuildSigner → deploy authorization | A signed kind-24242 event becomes authority for an HTTP request. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|

| T-162-16 | Elevation of Privilege | deploy-signer remote path | high | mitigate | Task 2 sends only kind 24242 templates and revalidates kind, signature, and signer identity before authorization use. |
| T-162-17 | Spoofing | Deno relay-pool adapter | high | mitigate | Task 1 delegates correlated verification to BuildSigner and proves every pool/subscription is aborted on completion or failure. |
| T-162-18 | Tampering | OS secret-store migration | high | mitigate | Task 2 preserves existing provider keys, selection, and fallback semantics and mutates storage only after verified pairing. |
| T-162-19 | Repudiation | CLI compatibility migration | medium | mitigate | Task 2 runs the complete pre-existing Deno suite after targeted tests and records the adapter migration atomically. |
