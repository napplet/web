# --proxy for HTTP and SOCKS5 proxies in the napplet CLI

Branch: `feat/cli-proxy`, cut from `origin/main` after #296. No protocol surface: the flag changes how the CLI reaches Blossom servers and relays, never what it publishes.

## Changes

- `d6ca035e` fix: nostr-tools resolves (rather than rejects) a publish with `connection failure: …` when a relay is unreachable, and the CLI counted it as published. Found while testing the proxy, where a wrong proxy would otherwise report every relay as published. Patch changeset and regression test.
- `ebd22ec3` feat: `--proxy <url>` on `deploy`, `init` and `keys connect` (`http`, `https`, `socks5`, `socks5h`, embedded credentials, never printed). Routes Blossom uploads, deploy and Zapstore publishing, `init` suggestions, and NIP-46 relay sessions including applesauce's NIP-11 lookup through one Deno HTTP client. Other commands reject the flag. Minor changeset; `rxjs` declared (already resolved via applesauce).

## Verification

- Probes confirmed Deno 2.9 routes `fetch` and `WebSocket` with `{ client }` through HTTP CONNECT and SOCKS5, and sends embedded proxy credentials for both.
- `tests/proxy_test.ts` end-to-end fixture: through both proxies every call site succeeds (Blossom HEAD and PUT, three relay sockets, NIP-11); directly, nothing connects. Same result as a QuickJS-compiled binary (the release engine).
- `pnpm build`, `pnpm type-check`, `pnpm -r test:unit` green (CLI 260 passed); aislop 98/100 baseline.

## Not covered

Managed tools started as child processes (screenshot capture, conformance, `paja`, npm package runs) are not proxied by the flag. No config-file or environment-variable setting for the proxy.
