# NAP-RESOURCE wire bytes and data: URL conformance

Spec: NAP-RESOURCE, napplet/naps#80 head `ae5b9c64ab8a4d8909f288829a01e99d6bd713bc` (§Byte encoding, §Schemas, §Schemes, §Sidecar Pre-Resolution) and `projections/web.md` at the same ref (§Resource binding → Bytes and local helpers).

## Gaps found

1. Every wire `blob` (bytes result, bulk item, `ResourceSidecarEntry`) MUST be canonical padded base64 (RFC 4648 §4). Code types it as `Blob` and the shim resolves it untouched; the web binding MUST validate + decode into a `Blob` typed with `mime`, MUST NOT accept Blob / ArrayBuffer / integer arrays, and invalid encoding MUST NOT reach a success callback or cache entry.
2. `data:` is decoded in the shim using the declared media type, with no size cap, MIME sniffing, SVG rasterization or quota (§Schemes `data:` row requires all of them wherever it's decoded).
3. `bytes()` pre-parses with `new URL()`, so bare `nhash` aliases (§Hashtree references) and malformed URLs never reach the runtime that owns `invalid-request`.
4. `ResourceScheme` omits `hashtree`.
5. Reference shell emits `Blob`s.

## Tasks

1. core: add `ResourceBytes` (string) wire alias; split wire item types (`ResourceBytesWireItem`) from API `ResourceBytesItem` (decoded `Blob`); `ResourceSidecarEntry.blob: ResourceBytes`.
2. nap/resource: strict canonical decoder (`decodeResourceBytes`), decode in result handlers (bytes rejects; bytesMany rejects whole call on bad encoding or malformed item shape); sidecar hydration decodes and skips invalid entries; route `data:` to the runtime; drop `new URL()` pre-parse; add `hashtree`.
3. conformance: reference shell emits base64; inbound validation if the engine validates `dir: 'in'`.
4. Tests (RFC 4648 §10 vectors + spec `AAEC/w==` vector + negatives), docs/JSDoc sweep, changesets, PR.
