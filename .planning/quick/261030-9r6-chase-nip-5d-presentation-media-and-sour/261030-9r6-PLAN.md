# Chase NIP-5D presentation media and source pin tags

## Spec delta (canonical: NIP-5D PR #2303, head `6e24617cde507c0a87fa170af9ed6b2b46545b2d`)

The current `5D.md` §Manifest tag table adds surface the repo does not handle:

| Tag | Cardinality | Section |
| --- | --- | --- |
| `screenshot` | 0+ | §Presentation media — NIP-92 `key value` fields; `x` required; `m`, `dim`, `size`, `alt` optional |
| `preview` | 0-1 | §Presentation media — same encoding; `duration` optional; multiple `preview` tags → clients ignore the preview |
| `source-commit` | 0-1 | §Source — exactly two elements, full lowercase-hex Git commit ID (40 or 64 chars); ignored without a Git repository `source` |
| `source-archive` | 0-1 | §Source — exactly four elements: absolute HTTPS URL without credentials or fragment, sha256, MIME type |
| `source` | 0-1 | §Source now also accepts `nostr://<naddr>` (NIP-34 clone URL) |
| `server` | 0+ | now hints the artifact, icon **and presentation** blobs |

§HTML Metadata for Publishing defines **no** head mapping for the new tags, so no `<meta>` surface is added (rule 1). The new tags live only in the sidecar / signed event.

## Tasks

1. **@napplet/conformance** — `validators/manifest.ts`: accept `nostr:` source locations; validate `source-commit` and `source-archive` (cardinality + shape, `invalid-metadata` errors, advisory when `source-commit` has no repository `source`); parse `screenshot` / `preview` NIP-92 fields and surface the spec's "ignore" rules as `invalid-presentation-media` warnings; export `parsePresentationMedia()` + `PresentationMedia` type so shells can apply the same rules. Tests in `manifest.test.ts`.
2. **@napplet/vite-plugin** — new `publishing-media.ts` (hash, size, MIME sniff and PNG/JPEG/WebP dimension reading for byte input; hash-only input; WebM/MP4 preview sniffing); options `screenshots`, `preview`, `sourceCommit`, `sourceArchive`; emit tags in the sidecar; write supplied media bytes to `dist/<sha256>.<ext>` so deploy tooling can upload them; never embed into HTML. Tests in `publishing-metadata.test.ts` / new `publishing-media.test.ts`; fixtures in `tests/fixtures`.
3. **@napplet/cli** — `manifest-media.ts` NIP-92 parser; `selectCurrentUploadFiles` keeps blobs referenced by `screenshot` / `preview` `x`; `buildCurrentManifestFields` validates the new tags; config `metadata.sourceCommit`, `metadata.sourceArchive`, `metadata.screenshots`, `metadata.preview` (local paths → hashed, sized, dimension-read, uploaded); `migrate.ts` drops unusable presentation media with a note; `normalizeSourceOverride` accepts `nostr://`. Deno tests.
4. **Docs / skills** — vite-plugin README + `apps/docs/packages/vite-plugin.md`; CLI README + `apps/docs/packages/cli.md`; conformance README; `apps/docs/guide/nip-5d.md`; `apps/docs/spec.md` drift notes; `skills/napplet-icon` / `napplet-test` mentions. No normative paraphrase; link the living text.
5. **Changesets** — conformance, vite-plugin, cli (patch: additive on 0.x).
6. **Verify** — `pnpm build`, `pnpm type-check`, `pnpm -r test:unit`, slop gate; push; open PR.

## Out of scope

- Inferring `source-commit` from Git HEAD at deploy time (a dirty or unpushed tree would pin a wrong revision; keep it explicit).
- Decoupling automatic deploy screenshot capture from Zapstore publication.
