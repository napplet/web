# Archetypes site and indexer

Build a browsable, searchable field guide to the archetypes (`z` tags) and intents (`i` tags) that napplet manifests advertise, at archetypes.napplet.run. Approved mockups: six boards (browse/search, archetype detail, synonym cluster, intent detail, agent surfaces, mobile).

## Protocol grounding

- NIP-5D (`5D.md` at PR #2303 head `f60550c`), §Manifest and §Archetypes and Intents: manifest kinds 5129/15129/35129; `["z", <archetype>]`; `["i", <intent>, <param>...]`; archetypes are ad hoc; a napplet with no `z`/`i` is valid.
- napplet/naps `ARCHETYPES.md`: NAAT registry deprecated, no replacement. Archetype names need no registration.
- Nothing here adds protocol surface. Curation (synonyms, diverse, param alignment) is editorial site data in `apps/archetypes/curation.yaml`, changed by PR, never written to relays. The site reads only `z` and `i`; the non-spec `archetype` tag some old events carry is ignored.
- Spec gap to flag (not fill): NIP-5D line 229 still says vocabulary is "defined outside this NIP by the archetype registry", which is deprecated.

## Tasks

1. `apps/archetypes-indexer` (Node 24, TypeScript, `node:sqlite`)
   - `config.ts`: one YAML file, every number defaulted; env for secrets only.
   - `relay-url.ts`: normalise and dedupe relay URLs.
   - `nip66.ts`: relay discovery from kind 30166 `d` tags on configured monitor relays.
   - `schedule.ts` (pure): points per napplet found, zero-point backoff ladder (1d, 3d, 7d, 14d, 30d), consecutive-failure removal, re-admission only on newer NIP-66 evidence.
   - `store.ts`: SQLite events (all three kinds, signature-verified) + per-relay sightings + relay state.
   - `relay-client.ts` + `crawl.ts`: REQ with `until` paging, incremental `since`.
   - `export.ts`: snapshot JSON for the site (events, ranked runtime relays = top N + pinned).
   - `deploy.ts`: Bunny Storage upload, stale-file delete, pull zone purge.
   - `service.ts`: loop (discovery, crawl due relays, daily build+deploy), `/healthz`, `/status`.
   - `Dockerfile` + `compose.yaml` (generic, no infrastructure specifics).
2. `apps/archetypes` (Astro, static)
   - `lib/model.ts`: index builder (dedupe releases, archetypes, intents, params, verbs, clusters, curation) shared by build and browser.
   - `lib/similarity.ts`: synonym candidate heuristics (name containment/tokens, publisher, verb, params, description).
   - Pages: `/`, `/archetypes/[slug]/`, `/intents/`, `/intents/[archetype]/[verb]/`, `/clusters/`, `/clusters/[id]/`, `/agents/`.
   - Machine surfaces: `/llms.txt`, `/llms-full.txt`, `/archetypes.json`, `/relays.json`, per-archetype `.md`, robots with AI agents allowed, sitemap, JSON-LD `DefinedTermSet`/`DefinedTerm`, WebMCP tool registration as progressive enhancement.
   - Live top-up: browser queries the build's runtime relays for events newer than the build and merges them through the same model.
   - Seed snapshot from the existing saved relay snapshot so CI and dev builds need no network.
3. Tests (vitest) for every module above; a built-site check script; screenshots for the PR.
4. Docs: READMEs for both apps, example config, curation guide.
5. Deploy: Bunny storage zone + pull zone + `archetypes.napplet.run` DNS/hostname; the indexer service on the operator's own infrastructure (wiring kept outside this repo).
