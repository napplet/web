# Expand the app store discovery relay pool

The app store still misses napplets that publishers only sent to relays outside the two-relay pool (`wss://relay.napplet.soy`, `wss://relay.damus.io`). Add `wss://relay.ditto.pub`, `wss://relay.primal.net` and `wss://relay.nostr.com` to `apps/web/src/data/discovery.json`. The relay list is site configuration, not protocol surface: NIP-5D defines the manifest kinds the site asks for, not where a shell or site looks for them.

1. `apps/web/src/data/discovery.json`: append the three relays. `wss://relay.napplet.soy` stays first because `scripts/check-app-store.mjs` treats `config.relays[0]` as the relay that advertises NIP-77 in its deterministic NIP-11 routing; the check's comments and assertion messages that say "both relays" and "the second" are generalised to "every configured relay" so they stay true for a pool of five.
2. `node scripts/refresh-showcase-apps.mjs`: refresh `apps/web/src/data/discovered-apps.json` from the wider pool, then `node --test scripts/refresh-showcase-apps.test.mjs` and the web unit tests, which read the saved snapshot.
3. `apps/web/README.md`: the app store section already defers to `discovery.json` for the relay list; confirm no stale two-relay wording remains (`grep -rn "damus" apps/web`) and adjust if any does.
4. Verify with `pnpm build`, `pnpm type-check`, `pnpm -r test:unit`, `node scripts/check-app-store.mjs` against the assembled site and the slop gate; commit by path on `feat/store-discovery-relays`, push, open the PR.

No changeset: `@napplet/web` is private.
